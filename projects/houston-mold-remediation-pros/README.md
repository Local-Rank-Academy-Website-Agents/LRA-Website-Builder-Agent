# Houston Mold Remediation Pros

A portable, zero-dependency static website for a pre-launch rank-and-rent property with 18 distinct service intents and 33 intended community targets across Greater Houston.

## Current status

This is a test build awaiting an operator, domain, and form destination. It is not ready for public indexing.

- No phone, address, storefront, Google Business Profile, license, review, price, guarantee, staff, or other unverified proof is published.
- Every substantive page has a unique FAQ section.
- Every service page has mapped Related Services and Service Areas sections.
- Every page contains `noindex,nofollow`, and the production build writes `Disallow: /` while `indexingEnabled` is `false`.
- The request form validates in the browser but does not transmit or store data.
- The canonical host uses the reserved `.invalid` top-level domain.

Read `LAUNCH-BLOCKERS.md` before deployment or indexing.

## View the site on localhost

### Windows

Double-click `VIEW-SITE.cmd`. It starts the local server and opens:

```text
http://localhost:4173/
```

Keep the command window open while viewing the site. Press `Ctrl+C` in that window when finished.

### Terminal

```bash
npm run view
```

To start the server without opening a browser:

```bash
npm run dev
```

Then visit `http://localhost:4173/`.

## Form activation

The form markup is generated by `scripts/generate-site.mjs`, and its browser behavior is in `site/assets/main.js`.

Before launch:

1. Select a secure form host, serverless endpoint, CRM webhook, or managed form product.
2. Keep secret keys on the server or hosting platform, never in browser JavaScript.
3. Add server-side validation, rate limiting, bot protection, and final consent language.
4. Replace the test-mode result with verified success, server-error, and timeout behavior.
5. Update the generated privacy content with the real controller, recipients, retention period, and contact.
6. Test delivery end to end with the operator who owns the destination.

## Domain and indexing activation

1. Resolve every item in `LAUNCH-BLOCKERS.md`.
2. Set the real `baseUrl` in `site.config.json`.
3. Set `indexingEnabled` to `true` only after operator, service, coverage, proof, routing, and privacy review.
4. Run `npm run check && npm run build`; the generator updates canonicals, Open Graph URLs, and robots metadata.
5. Verify `dist/robots.txt`, `dist/sitemap.xml`, structured data, 404 behavior, HTTPS, and preferred-domain redirects.

## Deployment

No host was selected. After all blockers are resolved, upload the contents of `dist/` to a static host that supports directory index files, `404.html`, HTTPS, preferred-host redirects, and the selected form integration.

Do not deploy the current package as an indexable production website.
